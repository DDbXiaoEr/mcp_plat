## 组件说明

### 外部访问层

系统有两个独立的访问入口：

| 入口 | 目标 | 说明 |
|------|------|------|
| 客户端A | APISIX | 通过API网关访问后端服务 |
| 客户端B | MCP Platform | 直接访问管理界面(端口8080) |

### APISIX 网关层

| 组件 | 端口 | 说明 |
|------|------|------|
| **APISIX** | 80, 443, 9180 | API网关，负责请求处理 |
| **Etcd** | 2379, 2380 | 配置中心，存储路由和插件配置 |

**go-runner插件：**
- **auth模块**: 调用accesskey-auth-server进行认证
- **audit模块**: 调用audit-log-server记录审计日志

### K8s 服务层

| 组件 | Service端口 | 说明 |
|------|-----|------|
| **accesskey-auth-server** | 端口1 | AccessKey认证服务 |
| **audit-log-server** | 端口2 | 审计日志服务 |

**K8s特性：** Deployment、Service ClusterIP、HPA、ConfigMap/Secret

### 应用层

| 组件 | 端口 | 说明 |
|------|------|------|
| **MCP Platform** | 8080 | 主应用，管理路由和插件配置，下发到Etcd |

### 数据层

| 组件 | 端口 | 说明 |
|------|------|------|
| **Main PostgreSQL** | 5432 | 主数据库，存储业务数据 |
| **ClickHouse** | 8123, 9000 | 审计数据库(ClickHouse版本) |
| **Audit PostgreSQL** | 5432 | 审计数据库(PostgreSQL版本) |

## 配置管理流程

```
1. 管理员通过MCP Platform配置路由和插件
2. MCP Platform将配置下发到Etcd
3. APISIX从Etcd同步配置
4. APISIX根据配置执行go-runner插件
```

## 请求处理流程

```
1. 客户端发送请求到APISIX
2. APISIX调用go-runner插件
3. go-runner auth模块调用accesskey-auth-server验证认证
4. go-runner audit模块调用audit-log-server记录审计日志
5. APISIX处理请求并返回响应
```

## 部署模式

| 模式 | 配置文件 | 审计存储 | 适用场景 |
|------|----------|----------|----------|
| ClickHouse版本 | docker-compose-clickhouse.yml | ClickHouse | 大数据量、高吞吐 |
| PostgreSQL版本 | docker-compose-postgres.yml | PostgreSQL | 数据量小、需事务 |

## 通信协议

| 通信链路 | 协议 | 说明 |
|----------|------|------|
| 客户端A → APISIX | HTTP/HTTPS | API访问入口 |
| 客户端B → MCP Platform | HTTP | 管理界面访问 |
| MCP Platform → Etcd | HTTP/gRPC | 下发配置 |
| APISIX → Etcd | gRPC | 同步配置 |
| go-runner → accesskey-auth-server | gRPC | 认证调用 |
| go-runner → audit-log-server | gRPC | 审计调用 |
| accesskey-auth-server → PostgreSQL | TCP | 数据库连接 |
| audit-log-server → ClickHouse/PostgreSQL | TCP | 数据库连接 |

## 网络

所有服务通过 `mcp_plat` Docker网络通信，K8s服务通过Service进行服务发现。
